# 5 Implementation

Everything is written in Python 3.14 against NumPy, SciPy, scikit-learn, and scikit-optimize, and kept in one version-controlled repository with the raw measurement logs, so that each figure and table can be regenerated by one script. The C++ tick-to-trade pipeline and the cloud provisioning of Appendix A have not been implemented.

## 5.1 Real-Measurement Harness

The harness (scripts/experiments/real_pilot.py) turns a configuration into one measurement. It normalises the configuration (Section 4.4), computes the CPU set the background load may use, reads the SMT sibling from the kernel's topology files rather than assuming it, starts stress-ng under taskset, waits two seconds, reads the interrupt counters, runs cyclictest with the requested affinity and policy, reads the counters again, and stops the load by signalling its process group so that no worker survives into the next measurement. Commands are built as argument lists and executed without a shell. Each measurement is appended as one JSON record containing the configuration, percentiles, overflow count, full histogram, per-CPU interrupt rates, load average, and timestamp. On start-up the harness skips every measurement already in the log, so an interrupted run resumes where it stopped and repeating a command can never overwrite data. The search driver uses the ask-and-tell interface of scikit-optimize, so the Gaussian process is updated after every real measurement, and it runs the re-evaluation and factorial phases in a seeded shuffled order, which makes the full sequence of 401 measurements reproducible. An earlier pilot with a synthetic Python trading loop had measured queueing delay instead of scheduling jitter because the offered load exceeded the service rate; that lesson is why cyclictest, which has no queue, was adopted.

## 5.2 Simulation Code

The synthetic model lives in scripts/experiments/bo_sim.py. The budget study (bo_budget.py) adds the exact ground truth by solving the mixture distribution numerically and verifying the optimum by enumeration over the full space, and the sensitivity study (bo_sensitivity.py) generalises this to perturbed models, saving the optimiser's state between invocations. It relies on the fact that the scikit-optimize proposals for a budget of 150 begin with exactly the proposals for smaller budgets, which was verified against independent runs for all seeds before being used. An early version drew only 20,000 samples per evaluation; at that size the 99.9th percentile rests on about 20 tail samples and the best observed configuration was largely the luckiest draw. The reported studies therefore use one million samples, and the same lesson motivated the re-evaluation phase of the real study.

## 5.3 Analysis and Testing

The real study is analysed by real_pilot_analyse.py, which reconstructs histograms from the log and computes the percentiles, bootstrap intervals, effect sizes, and factorial model; the follow-up of Section 6.4 reuses the harness (cstate_followup.py). Every number in Chapter 6 was transcribed from these generated outputs. Unit tests, which run in under a minute, cover the normalisation rules, the CPU sets given to the load, the command lines, histogram parsing, the treatment of overflows, and percentile extraction; one test caught a floating-point error in the percentile rank before any data were collected. A smoke test takes two real three-second measurements and checks that no stress-ng worker is left behind. For the simulation, tests check determinism, the direction of every modelled effect, the agreement between exact and Monte Carlo percentiles, and the equivalence of budget prefixes. A miniature run of all four phases was executed before the four-hour run.
