# 5 Implementation

Everything is written in Python 3.14 against NumPy, SciPy, scikit-learn, and scikit-optimize, and kept in one public repository with the raw measurement logs (Appendix C), so that each figure and table can be regenerated by one script. The tick-to-trade pipeline and cloud provisioning of Appendix A have not been implemented.

## 5.1 Real-Measurement Harness

The harness (scripts/experiments/real_pilot.py) turns a configuration into one measurement. It normalises the configuration, computes the CPU set the background load may use, reads the SMT sibling from the kernel's topology files, starts stress-ng under taskset, waits two seconds, reads the interrupt counters, runs cyclictest with the requested affinity and policy, reads the counters again, and stops the load by signalling its process group so that no worker survives into the next measurement. Each measurement is appended as one JSON record with the configuration, percentiles, full histogram, per-CPU interrupt rates, load average, and timestamp. On start-up the harness skips every measurement already in the log, so an interrupted run resumes where it stopped and repeating a command never overwrites data. The search driver uses the ask-and-tell interface of scikit-optimize, so the Gaussian process is updated after every real measurement, and runs the later phases in a seeded shuffled order, so the order of the 401 measurements is reproducible. An earlier pilot with a synthetic Python trading loop had measured queueing delay instead of scheduling jitter because its offered load exceeded the service rate, which is why cyclictest, which has no queue, was adopted.

## 5.2 Simulation Code and Testing

The synthetic model lives in bo_sim.py; bo_budget.py adds the exact ground truth by solving the mixture distribution numerically and verifying the optimum by enumeration, and bo_sensitivity.py generalises this to perturbed models, saving the optimiser's state between invocations. An early version drew only 20,000 samples per evaluation, at which the 99.9th percentile rests on about 20 tail samples and the best observed configuration was largely the luckiest draw; the reported studies use one million samples, and the same lesson motivated Phase C of the real study. Unit tests cover the normalisation rules, the CPU sets given to the load, the cyclictest and stress-ng command lines, histogram parsing, overflows, and percentile extraction, including a fixture for a floating-point error in the nearest-rank computation found before any data were collected; simulation tests check determinism, the direction of the main modelled effects, the agreement between exact and Monte Carlo percentiles, and that a search chain saved and resumed in segments reproduces an unsegmented one. A smoke test takes two real three-second measurements and checks that no stress-ng worker is left behind, and a miniature run of all four phases preceded the four-hour run; both need a raised RLIMIT_RTPRIO.
