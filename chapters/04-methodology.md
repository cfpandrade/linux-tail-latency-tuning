# 4 Methodology

## 4.1 Research Design

The study combines two executed strands and one specified but unexecuted strand. The first is a controlled empirical study on a commodity Linux workstation, every data point a real measurement of scheduling latency under contention; it answers RQ1 and gives the real-measurement test of RQ2. The second is a simulation study on a synthetic latency model whose optimum is known exactly; it says nothing about real kernels, but it can score a search procedure against a known answer, which no real measurement can, and so answers RQ2 in that sense and RQ3. The third is the cloud study proposed originally (Appendix A). The strands constrain each other: the simulation budget study, run first, set the real budget, and the real measurements show which simulation assumptions hold on hardware. A controlled experiment was chosen over observation of a production system because the research questions concern causal effects. The stance is post-positivist: latency effects are treated as real and measurable, but every estimate is reported with its uncertainty and conditions, since one host and one kernel cannot establish general laws.

## 4.2 Experimental Platform

All real measurements were taken on one workstation: an Intel Core i7-8700 (six cores, twelve hardware threads, one NUMA node), 30 GiB of memory, Ubuntu 26.04.1 LTS with the generic 6.17 kernel (PREEMPT_DYNAMIC, 1000 Hz tick, not PREEMPT_RT), no isolcpus, nohz_full, or rcu_nocbs boot parameters, irqbalance not running, and no frequency-scaling driver exposed to user space (recorded in data/real_pilot/run1/platform.json). No experiment ran as root; the only privilege was a raised RLIMIT_RTPRIO of 99, which lets an unprivileged process request SCHED_FIFO. This deliberately limits the study to mechanisms an application team can apply without changing the kernel or its boot parameters, as in managed environments.

## 4.3 Workload and Instrumentation

The latency-critical component of a tick-to-trade path is a thread that must run as soon as an event arrives, and the quantity measured is its wake-up latency, the delay between a timer falling due and the thread running, measured with cyclictest 2.80 from the rt-tests suite [@rttests2024cyclictest]. One thread wakes every 200 microseconds, so a 30-second measurement yields about 150,000 samples, recorded in a histogram with 1-microsecond bins up to 20 milliseconds; samples beyond the last bin are treated as right-censored. This measures only the scheduling component of the critical path, on a single clock, so no external time synchronisation is needed.

Contention is created with stress-ng [@king2024stressng]: one matrix-multiplication worker on each CPU the configuration allows, plus two memory workers each touching 256 MiB, started two seconds before the measurement and stopped after it; the load is identical across configurations except where one deliberately keeps it off some CPUs. Before and after each measurement the harness records per-CPU interrupt and local-timer rates and the load average, to help identify the mechanism behind a change in the tail.

## 4.4 Tuning Mechanisms and Search Space

Five parameters define a configuration (Table 4.1). Equivalent combinations are normalised before measuring (priority is irrelevant under SCHED_OTHER, isolation is meaningless for an unpinned thread, and sibling exclusion applies only when the core is isolated), leaving 3,700 distinct configurations: 37 under SCHED_OTHER and 3,663 under SCHED_FIFO. Isolation is achieved in user space by restricting the affinity of the background load, not with isolcpus, so it removes user-space competition from the measured core but leaves kernel threads, timers, and interrupts there. The untuned default is SCHED_OTHER, unpinned, with the load free to run anywhere.

| Parameter | Values | Mechanism |
|--------------|---------------------------|-----------------------------------------------------|
| policy | SCHED_OTHER or SCHED_FIFO | Scheduling class of the measured thread |
| rt_priority | 1 to 99 | SCHED_FIFO priority (ignored under SCHED_OTHER) |
| cpu | unpinned, or CPU 0 to 11 | CPU affinity of the measured thread |
| isolate | off or on | Background load kept off the measured CPU |
| sibling_free | off or on | Background load also kept off the SMT sibling |

## 4.5 Experimental Phases

The real study runs in four phases of 30-second measurements. Phase A (baseline) measures the untuned default ten times. Phase B (search) lets Bayesian optimisation and random search each choose 30 configurations for five seeds, interleaved so that slow drift affects both equally; each method's pick for a seed is the configuration with the lowest observed 99.9th percentile. Phase C (re-evaluation) measures every pick and the default five more times in shuffled order, because the minimum of 30 noisy observations is partly the luckiest draw; only these measurements are used to compare methods or claim an improvement. Phase D (factorial) measures twelve configurations three times each in shuffled order: both policies (SCHED_FIFO at priority 80), three isolation levels (none, core isolated, core and sibling free), and two CPUs (CPU 0, which handles more device interrupts by default, and CPU 5). The study comprises 401 measurements, about 3.6 hours; a 35-measurement follow-up testing one unexpected result is reported in Section 6.4.

## 4.6 Search Procedures

The objective is the base-10 logarithm of the measured 99.9th percentile, because tail latencies span several orders of magnitude and a Gaussian process models the logarithm far better. The surrogate is the Gaussian process regressor of scikit-optimize [@head2021skopt], version 0.10.2, with the same settings in both studies. Each configuration is mapped to a unit cube (integers scaled to 0 to 1, binary parameters as 0 or 1). The kernel is a constant amplitude multiplied by an anisotropic Matérn kernel of smoothness 5/2, one length scale per dimension, plus a white-noise term [@snoek2012practical]; amplitude, length scales, and noise level are re-fitted by maximising the marginal likelihood after every observation, from two restarts, on the standardised objective. The next configuration maximises expected improvement over the best observed value [@jones1998efficient] with an exploration offset of 0.01: 10,000 random candidates are scored, the best five refined with L-BFGS-B, and the result rounded to the grid. Each seed starts from eight configurations drawn uniformly at random, since seven hyperparameters cannot be fitted from fewer observations, and the model proposes the remaining 22. The budget of 30 evaluations per seed follows from the simulation budget study (Section 6.5), which placed the separation between the methods at 20 to 40 evaluations, and from measurement time, since two methods and five seeds already take 300 of the 401 measurements. Random search draws each configuration independently and uniformly from the same unit cube, under the same budget, seeds, and interleaving [@bergstra2012random; @turner2021bbo], so it chooses SCHED_FIFO with probability one half; the methods differ only in how the next point is chosen, so any difference between them is attributable to the surrogate and acquisition function, not to budget, bounds, or noise. The best observed value is still partly the luckiest draw, which is why Phase C re-measures every pick.

## 4.7 Simulation Study

The simulation replaces measurement with a synthetic model in which each request has a log-normal body latency and, with some probability, a Pareto-distributed stall. Eight tuning parameters (isolated cores, IRQ affinity, nohz_full, PREEMPT_RT, frequency governor, NUMA pinning, real-time priority, and interrupt coalescing) act through 24 coefficients, 22 of them perturbable, chosen by hand to mimic the qualitative behaviour reported in the literature (Table B.5). Because the model is explicit, its exact 99.9th percentile can be computed for every one of the 2,879,712 configurations, so every pick is scored by its regret, the ratio of its true 99.9th percentile to the optimum, minus one. Each noisy evaluation draws one million samples. The budget study runs both methods at budgets of 10, 20, 40, 80, and 150 evaluations, 30 seeds each; Bayesian optimisation draws its first 10 points at random, so at a budget of 10 it is itself a random search. The sensitivity study perturbs each coefficient one at a time by factors of 0.5, 0.75, 1.5, and 2 (88 models; rules in Table B.5), with a planned joint sweep of 128 models along a scrambled Sobol sequence [@sobol1967distribution], and repeats the budget study on every model.

## 4.8 Metrics and Statistical Analysis

The primary metrics are the 50th, 99th, and 99.9th percentiles of wake-up latency (p50, p99, p99.9) and the maximum. The statistical unit is one 30-second measurement, because samples within a measurement are serially dependent. A configuration is summarised by the median of its runs' percentiles and by the percentile of the pooled histogram of its runs, with a 95 per cent interval from a bootstrap over whole runs (5,000 resamples); with three runs the interval is indicative only. Differences against the default are summarised by Cliff's delta [@cliff1993dominance]. The picks of the two methods are compared with the Vargha-Delaney A12 statistic [@vargha2000critique], which alone decides whether H2 is refuted, and with a one-sided Mann-Whitney U test [@mann1947test] for the advantage H2 anticipates. The factorial phase is analysed with a main-effects linear model on the logarithm of p99.9, checked with a lack-of-fit test, so that each coefficient is a multiplicative effect on the tail. Tests use a significance level of 0.05. In the simulation, regret replaces latency and parameter importance is measured by exact total-effect Sobol indices [@sobol2001global], with SHAP values of a random forest fitted to the random-search trials [@lundberg2017unified] as the estimate an analyst without the true model could make. A Kolmogorov-Smirnov test was not used because with 150,000 autocorrelated samples per run it flags trivial differences.

## 4.9 Legal, Social, Ethical, and Professional Issues

Ethically, the workload is entirely synthetic, with no market data, order entry, exchange connection, human participants, or personal data, so there is no risk of market impact and the project falls outside research ethics review; the Ethical Considerations Form was submitted at proposal stage with all questions answered negatively. The experiments ran on the author's own workstation without administrative privileges and affected no other users; a SCHED_FIFO thread at priority 99 could in principle starve a CPU, but the measured thread sleeps for most of each 200-microsecond period and the kernel's default real-time throttling remained in place.

Legally, the tools used are open source, and the repository publishes the code under the MIT licence and the text and figures under CC BY 4.0. The clock-accuracy rules of MiFID II [@ec2017rts25] motivate the work but impose no obligation on a laboratory study that records no business events. Socially, lower tail latency serves an industry whose benefits are contested, but the same mechanisms govern telemetry, control, audio, and payment systems, and the published harness lets those communities reuse the method. Professionally, the study follows the BCS Code of Conduct in working within the author's competence, reporting unexpected and negative results (Section 6.4) as fully as positive ones, and making every number in Chapter 6 regenerable from the published code and raw logs (Appendix C).
