# 4 Methodology

## 4.1 Research Design

The study combines two executed strands and one specified but unexecuted strand. The first is a controlled empirical study on a commodity Linux workstation, in which every data point is a real measurement of scheduling latency under contention; it answers RQ1 and provides the real-measurement test of RQ2. The second is a simulation study on a synthetic latency model whose true optimum is known exactly. It says nothing about real kernels, but it can say how well a search procedure performs against a known answer, which no real measurement can, and so it answers RQ2 in that controlled sense and RQ3. The third strand is the cloud study proposed originally, outlined in Appendix A. The two executed strands constrain each other: the simulation justifies the budget spent on the real host, and the real measurements show which of the simulation's qualitative assumptions hold on hardware. An experimental design was chosen over observation of a production system because the research questions concern causal effects of individual mechanisms, which only controlled variation can isolate.

## 4.2 Experimental Platform

All real measurements were taken on one workstation: an Intel Core i7-8700 (six cores, twelve hardware threads, one NUMA node), 30 GiB of memory, Ubuntu 26.04.1 LTS with the generic 6.17 kernel (PREEMPT_DYNAMIC, 1000 Hz tick, not PREEMPT_RT), no isolcpus, nohz_full, or rcu_nocbs boot parameters, irqbalance not running, and no frequency-scaling driver exposed to user space. No experiment ran as root; the only privilege was a raised RLIMIT_RTPRIO of 99, which lets an unprivileged process request SCHED_FIFO. This restriction is deliberate: it limits the study to mechanisms an application team can apply without changing the kernel or its boot parameters, a realistic constraint in managed environments, and it keeps the experiment safe to run unattended.

## 4.3 Workload and Instrumentation

The latency-critical component of a tick-to-trade path is a thread that must run as soon as an event arrives. The quantity measured is that thread's wake-up latency, the delay between the moment a timer was due to fire and the moment the thread runs, measured with cyclictest 2.80 from the rt-tests suite [@rttests2024cyclictest]. One thread wakes every 200 microseconds, so a 30-second measurement yields about 150,000 samples, recorded in a histogram with 1-microsecond bins up to 20 milliseconds; samples beyond the last bin are treated as right-censored. This measures the scheduling component of the critical path only, on a single clock, so no external time synchronisation is needed.

Contention is created with stress-ng [@king2024stressng]: one matrix-multiplication worker on each CPU the configuration allows, plus two memory workers each touching 256 MiB, started two seconds before the measurement and stopped after it. The load is identical across configurations except where a configuration deliberately keeps it off some CPUs. Before and after each measurement the harness reads /proc/interrupts and stores the interrupt and local-timer rates of every CPU, with the load average, so that the mechanism behind a change in the tail can be identified.

## 4.4 Tuning Mechanisms and Search Space

Five parameters define a configuration (Table 4.1). Equivalent combinations are normalised before measuring (priority is irrelevant under SCHED_OTHER, isolation is meaningless for an unpinned thread, and sibling exclusion applies only when the core is isolated), leaving 3,700 distinct configurations: 37 under SCHED_OTHER and 3,663 under SCHED_FIFO. Isolation is achieved in user space by restricting the affinity of the background load, not with isolcpus; it removes user-space competition from the measured core but leaves kernel threads, timers, and interrupts there. The untuned default is SCHED_OTHER, unpinned, with the load free to run anywhere.

| Parameter | Values | Mechanism |
|--------------|---------------------------|-----------------------------------------------------|
| policy | SCHED_OTHER or SCHED_FIFO | Scheduling class of the measured thread |
| rt_priority | 1 to 99 | SCHED_FIFO priority (ignored under SCHED_OTHER) |
| cpu | unpinned, or CPU 0 to 11 | CPU affinity of the measured thread |
| isolate | off or on | Background load kept off the measured CPU |
| sibling_free | off or on | Background load also kept off the SMT sibling |

## 4.5 Experimental Phases

The real study runs in four phases of 30-second measurements, logged to an append-only file so that a run can resume after interruption. Phase A (baseline) measures the untuned default ten times. Phase B (search) lets Bayesian optimisation and random search each choose 30 configurations for five independent seeds, interleaved so that slow drift affects both equally; each method's pick for a seed is the configuration with the lowest observed 99.9th percentile. Phase C (re-evaluation) measures every pick and the default five more times in shuffled order, because the minimum of 30 noisy observations is partly the luckiest draw, and only these measurements are used to compare methods or claim an improvement. Phase D (factorial) measures twelve configurations three times each in shuffled order: both policies (SCHED_FIFO at priority 80), three isolation levels (none, core isolated, core and sibling free), and two CPUs (CPU 0, which handles more device interrupts by default, and CPU 5). The study comprises 401 measurements, about four hours. A follow-up of 35 measurements, added afterwards to test an explanation for one unexpected result, is reported separately in Section 6.4 so that the pre-planned analysis stays distinct from the explanatory one.

## 4.6 Search Procedures

The objective is the base-10 logarithm of the measured 99.9th percentile, because tail latencies span several orders of magnitude and a Gaussian process models the logarithm far better than the raw value. The surrogate is a Gaussian process with a Matérn kernel as implemented in scikit-optimize, and the next configuration is chosen by expected improvement [@jones1998efficient; @snoek2012practical] after eight random initial configurations per seed. Random search samples each parameter independently and uniformly [@bergstra2012random], so it chooses SCHED_FIFO with probability one half. Measurement noise is modelled only through the Gaussian process's noise term, which is why Phase C re-measures every pick.

## 4.7 Simulation Study

The simulation replaces measurement with a synthetic model in which each request has a log-normal body latency and, with some probability, a Pareto-distributed stall, which produces a heavy tail. Eight tuning parameters (isolated cores, IRQ affinity, nohz_full, PREEMPT_RT, frequency governor, NUMA pinning, real-time priority, and interrupt coalescing) act through 22 coefficients chosen by hand to mimic the qualitative behaviour reported in the literature. Because the model is explicit, its exact 99.9th percentile can be computed for every one of the 2,879,712 configurations, so the optimum is known and every pick is scored by its regret, the ratio of its true 99.9th percentile to the optimum, minus one. Each noisy evaluation draws one million samples. The budget study runs both methods at budgets of 10, 20, 40, 80, and 150 evaluations, 30 seeds each; Bayesian optimisation draws its first 10 points at random, so at a budget of 10 it is itself a random search. The sensitivity study perturbs each coefficient one at a time by factors of 0.5, 0.75, 1.5, and 2 (88 models), with a planned joint sweep of 128 models along a scrambled Sobol sequence [@sobol2001global], and repeats the budget study on every model.

## 4.8 Metrics and Statistical Analysis

The primary metrics are the 50th, 99th, and 99.9th percentiles of wake-up latency (p50, p99, p99.9) and the maximum. The statistical unit is one 30-second measurement, because samples within a measurement are serially dependent. A configuration is summarised by the median of its runs' percentiles and by the percentile of the pooled histogram of its runs, with a 95 per cent interval from a bootstrap that resamples whole runs 5,000 times; with three runs the interval is indicative only. Differences against the default are summarised by Cliff's delta [@cliff1993dominance], the picks of the two methods are compared with the Mann-Whitney U test [@mann1947test] and the Vargha-Delaney A12 statistic [@vargha2000critique], and the factorial phase is analysed with a main-effects linear model on the logarithm of p99.9, checked with a lack-of-fit test, so that each coefficient is a multiplicative effect on the tail. Tests use a significance level of 0.05. In the simulation, regret replaces latency and parameter importance is measured by exact total-effect Sobol indices, with SHAP values of a random forest fitted to the random-search trials [@lundberg2017unified] as the estimate an analyst without the true model could make. A Kolmogorov-Smirnov test was rejected because with 150,000 autocorrelated samples per run it detects trivial differences.

## 4.9 Ethical and Professional Considerations

The workload is entirely synthetic: no market data, order entry, or exchange connection is involved, so there is no risk of market impact or regulatory breach, and no human participants or personal data are implicated. The project therefore falls outside the scope of research ethics review, and the Ethical Considerations Form was submitted at proposal stage with all questions answered negatively. The experiments ran on the author's own workstation without administrative privileges, so they could not damage the system or affect other users. All code, raw logs, and analysis scripts are published so that every number in Chapter 6 can be regenerated.
